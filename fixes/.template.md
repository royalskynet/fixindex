WHAT BELONGS HERE — one rule

    Symptom before narrative.

A fix log is a reproducible, work-saving technical note. Write an entry
when you have FIXED A DEFECT — not when a phase completed, a task
shipped, or a session wrapped up. Diagnosis without a fix is fine: say
"not fixed yet" and record the next step. The diagnosis is the asset.

If you cannot write a Symptom someone could grep for, you do not have
an entry. You have a status report — put it somewhere else.

DO NOT WRITE
─────────────────────────────────────────────────────────────────────
  ✗ Dates in filenames            0042-thing-20250105.md
                                  → the entry is about the defect, not the day

  ✗ "## §N Correction (date)"     Amending your own earlier report is a
                                  conversation artifact. Edit §1 in place.

  ✗ Verify as a one-off reading   "quota 348/1000, error rate 2.3%"
                                  → tomorrow it reads differently and proves
                                    nothing. Verify must be a RERUNNABLE
                                    command plus the expected result.

  ✗ Fix as project progress       "Phase 3 introduced the new pool"
                                  "fixed in Block B of the plan"
                                  → meaningless once that document is gone.
                                    Write the command or the diff.

  ✗ Metrics in `symptoms:`        "50.8% / 49.2% split", "PID 81681",
                                  "6 occurrences on 2025-01-05"
