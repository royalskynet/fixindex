讀完這個目錄下的 {PART}（已脫敏的 session 逐字稿片段），從頭讀到尾，不抽樣。不要讀其他檔，不要建立、修改或刪除任何檔案。

只列下次在別的專案、別台機器還會再撞到的技術經驗。不設條數上限：符合下面條件的都列，後面有查重與裁決把關；不符合的一條都不列。
- symptom 要同時符合：逐字稿裡有錯誤訊息原文、非零結束碼或錯誤輸出；查到了根因；修法實測過。
- insight 只收推翻了一個原本合理假設的發現，而且逐字稿裡有實測數字或輸出佐證。
- 不列：這次做了什麼的流水帳；本機或本專案的慣例、流程規定、派工規則；機制照設計運作的說明；沒有錯誤原文只有結論的心得；RULE 拿掉專案名後只剩「先確認再做」「要回報」這類常識。
同一個根因或同一條規則只列一次：列之前先跟你已列的比，同主題就併進同一條。

每個候選輸出一行 JSON，不要包在 code block 裡，不要換行。兩種格式擇一：
{"kind":"symptom","core":"≤80 字核心","query":"查重用核心關鍵字","quote":"逐字引用","fields":{"SYMPTOM":"…","ROOT":"…","FIX":"…","VERIFY":"…","RULE":"…"}}
{"kind":"insight","core":"≤80 字核心","query":"查重用核心關鍵字","quote":"逐字引用","fields":{"CONTEXT":"…","INSIGHT":"…","IMPLICATION":"…","QUERIES":"…","RULE":"…"}}

規則：
- quote：從 {PART} 複製同一行內連續 ≥12 字的原文（報錯原文、指令輸出或使用者原話），一字不改。找不到能佐證的原文就不要列這個候選。
- RULE 必填：拿掉專案名後仍成立的可泛化規則。
- 欄位值寫可搜尋的關鍵字（錯誤訊息原文、指令名、設定鍵），不寫「這次」「剛才」。
- 不還原 <MASKED_*>、<PERSON_1> 這類佔位符，不猜原值。
- 沒有可記的就只輸出一行：NONE
